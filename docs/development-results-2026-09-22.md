## 실제 변경 사항

### 분석 경로 복구와 상태 표시

- Tree-sitter 입력을 UTF-8 바이트로 전달하고 현재 트리·노드 API로 결과를 읽는다.
- 같은 문법·입력의 파싱을 캐시한다. 성능 향상 수치는 별도로 측정하지 않았다.
- 문법 분석·휴리스틱 대체·입력 부재를 `scan_metrics.analysis_notes`에 기록한다.
- 언어 의존성을 고정하고 GitHub Action도 패키지 의존성을 함께 설치한다.
- 추가된 줄과 삭제된 줄을 따로 분석한다. 주석 줄만 바뀐 라우트 예시의 오탐을 줄였다. 문자열·줄 끝 주석에서는 오탐이 남아 있다.

### 삭제·입력 누락 처리

- 삭제된 API의 계약 변경을 탐지한다.
- 최소 변경 수준이 설정된 규칙에서 patch 누락·대용량 생략·바이너리 생략을 낮은 강도의 변경으로 간주하지 않는다.
- 분석 입력이 없으면 필요한 분석 증거를 미충족 항목으로 표시한다.
- GitHub의 `removed`를 내부 `deleted`로 통일한다. 삭제된 문서와 요구 경로 밖으로 이동한 문서는 문서 수정 조건을 충족하지 못한다.

### 확인 가능한 승인만 예외에 사용

- PR 본문의 `approved-by`와 검증된 승인 증거를 분리했다.
- base revision의 CODEOWNERS와 head commit의 실제 리뷰 승인을 조회한다.
- 담당자·쓰기 권한·팀 소속과 팀 저장소 권한·승인 철회·오래된 커밋·수집 중 커밋 변경을 확인한다.
- 검증 실패 시 예외를 허용하지 않고 정상 승인에서는 허용한다.
- 감사 기록에 승인 검증 여부와 대상 커밋을 추가했다.
- 여러 예외 요청이 서로의 사유·만료일을 가져오는 파싱 문제를 수정했다.

외부 연동 검증에는 통제된 GitHub API 응답을 사용했다. 실제 조직의 토큰 권한이나 실 PR에서 실행한 결과가 아니다. 지원하는 CODEOWNERS 문법과 실패 시 동작은 [사용 안내](content-verification.md)에 적었다.

### 문서 내용 증거 확인

- 인식 가능한 API 경로 변경은 문서 diff에서 대응하는 HTTP 메서드·경로의 추가와 삭제를 확인한다.
- 무관한 문서의 오타 수정으로 API 검사를 통과할 수 없도록 했다.
- `content: env-keys` 정책으로 새 키가 `.env.example`의 현재 내용에 있는지 확인한다.
- 샘플이 바뀌지 않았어도 키가 이미 있으면 통과한다. 다른 키나 주석만 추가하면 실패한다.
- 새 문서 읽기 경로는 값 대신 키 이름만 보존한다. 임시 Git 저장소의 CLI 통합 테스트로 실제 파일 읽기와 종료 코드를 확인했다.
- `content: paths`로 기존 파일 동반 수정 방식도 선택할 수 있다.

## 비교 조건과 원본 증거

기존 비교에서는 fixture 22개, 개선 목표 8개, 측정 스크립트의 SHA-256이 기준값과 같음을 확인했다. Python·운영체제·기록한 주요 의존성 버전도 같다. 기준값 파일은 수정하지 않았다.

환경변수 평가셋은 첫 기준값에 없었으므로, 원래 커밋을 임시 디렉터리에 `git archive`로 추출한 뒤 동일한 새 평가셋·측정 스크립트로 이전 제품 코드와 개선 제품 코드를 각각 실행했다. 이전 결과를 추정해서 기입하지 않았다.

환경변수 평가는 **엔진 수준의 합성 비교**다. 두 버전에 동일한 파일 목록·문서 키 이름 증거를 전달하며, 기존 모델은 새 content 설정과 키 증거를 사용하지 않는다. unchanged 문서 입력도 동일하게 제공했다. 별도의 CLI 통합 테스트가 현재 버전의 실제 파일 읽기를 검증한다. 실 PR 성능으로 합산하지 않는다.

## 남은 과제

1. 원본 PR과 SHA를 추적할 수 있는 실제 PR 30~50개 수집 및 별도 평가.
2. 전체 파일의 변경 전후 AST 비교, 라우터 prefix·계산된 경로, 중첩 OpenAPI YAML, 요청·응답 스키마와 자유 형식 문서 검증.
3. 동적 환경변수 키·별칭·프레임워크별 설정 모델 지원. 현재는 정적으로 확인 가능한 키에 한정한다.
4. GitHub Action 실행 간 이력 복원, 동일 PR 재실행 중복 제거, 실제 해결 시간 검증.
5. 실제 GitHub 권한 환경과 다중 운영체제 CI 실행. 현재는 로컬 테스트와 어댑터 모의 검증까지 완료했다.
