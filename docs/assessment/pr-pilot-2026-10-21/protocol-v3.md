# 실제 PR 파일럿 — 규칙 수정 (v3)

작성: 2026-10-21 · [protocol.md](protocol.md), [protocol-v2.md](protocol-v2.md)는 고치지 않는다. 엔진 결과(`holdout run`)는 아직 한 번도 실행하지 않았고 정답 label도 없다.
표본(30개 PR), 정책 3개, 선정 규칙은 그대로이며 다시 뽑지 않는다.

## 바뀐 점과 이유 (코드·구조 검토에서 발견)

| # | v2 | v3 | 이유 |
|---|---|---|---|
| 1 | 사례의 `changed_files`에 PR이 바꾼 파일만 있음 | 정책이 요구하는 문서(`.env.example`, `docs/openapi/openapi.json`)를 PR 커밋 시점 내용으로 붙인다(엔진의 `attach_env_documents`를 그대로 호출, `status: unchanged`) | 제품 경로(CLI·Action·불변 검사)는 요구 문서를 붙이는데 v2 사례에는 없어, 새 키를 `.env.example`에 같이 넣은 PR이 "문서 입력 없음"으로 보류되고 넣지 않은 PR은 이미 문서에 있는 키도 위반으로 나왔다(합성 입력으로 재현). 측정 대상이 엔진이 아니라 수집 코드의 누락이 된다 |
| 2 | 검토 시트에 변경 파일 diff만 있음 | 규칙 경로에 걸린 PR은 요구 문서의 PR 커밋 시점 원문(키 줄·API 경로 목록)을 함께 보여 준다 | 바뀌지 않은 문서를 볼 수 없으면 검토자도 "이미 반영되어 있는가"를 판단할 수 없다. 원문에서 직접 요약하며 엔진 해석 필드는 packet에 없다 |
| 3 | PR 단위 label을 "정책 gate 기준"으로 설명 | 저장소 관례 기준으로 풀어 쓴 설명을 시트에 붙인다(fail=병합 전 고쳐야 할 문서 누락, warn=확정 불가·의심, pass=누락 없음) | 정책 내부 설정(`on_unverified` 등)을 맞히는 질문이 되지 않게 함. 허용 label과 도구 동작은 바뀌지 않음 |
| 4 | 엔진 버전 미고정 | `holdout run` 직전에 엔진 커밋을 `engine-pin.md`에 기록하고, 그 뒤 엔진을 고치지 않는다 | 라벨 이후 엔진 수정이 결과를 바꾸는 것을 막음. 코드 검토에서 나온 엔진 수정은 이 파일럿 사례를 사용하지 않고 합성 입력으로 재현한다 |

## 폐기와 보존

v2 산출물(`manifest.md`의 해시, 이전에 전달한 `review-sheet.md`)은 엔진을 한 번도 실행하지 않은 채 폐기한다. 파일은 지우지 않고 문서에 남긴다. 검토자는 v3 시트만 사용한다.
