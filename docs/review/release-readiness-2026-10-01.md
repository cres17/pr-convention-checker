## 설치 패키지에서 발견한 추가 오류

저장소 밖의 새 환경에 wheel을 설치하자 `demo`가 기본 평가 파일을 찾지 못하고 **0개 평가·성공**으로 종료했다. 실행 폴더에 상대적인 경로를 패키지 내부 경로로 바꾸고 평가 JSON을 배포 패키지에 포함했다. `demo`, `eval`, `drift-gate-eval` 모두 입력이 비어 있으면 종료 코드 2로 실패하게 했다.

같은 여섯 검사(명령 세 개 × 외부 폴더 기본 실행·빈 입력)를 원본과 수정본에 적용한 결과 **0/6 → 6/6 충족**이다. 새로 빌드한 wheel을 별도 환경에 설치해 CLI 기본 데모·평가와 포함된 UI 파일을 확인했다. 기본 평가는 최상위 21개, 재귀 평가는 하위 폴더의 사례까지 22개다. 평가가 없는데 정확도가 100%처럼 보이는 결과를 더는 만들지 않는다.

## 파일 정리

- OS의 `.DS_Store`, 로컬 보관 폴더, 생성된 native 패키지는 Git에서 제외한다.
- 기존 `reviews/` 전달용 파일은 복사 후 SHA-256을 대조한 뒤 `.local-archives/cleanup-20261001/`로 옮겼다. 이미 적용된 과거 패치를 중복 공개하지 않는다.
- 과거 평가와 스킬 적용 근거는 보존한다. 삭제해 검증 이력을 깔끔하게 보이도록 하지 않는다.
- `CLAUDE.md`의 오래된 패키지 구조와 고정 테스트 수를 갱신했다. 문서 탐색은 [문서 안내](../README.md)에서 시작할 수 있다.
- 평가 원본은 `assessment/`, 분석은 `review/`, 디자인은 `design/`, 운영은 `ops/`, 설치 파일은 GitHub Releases에 둔다.

## 릴리스 상태

[desktop-v1.0.1-preview.20261001](https://github.com/cres17/pr-convention-checker/releases/tag/desktop-v1.0.1-preview.20261001)을 게시했다. 제품 커밋은 `6445879`이고 [워크플로 36804667492](https://github.com/cres17/pr-convention-checker/actions/runs/36804667492)의 세 플랫폼 빌드와 릴리스 작업이 성공했다. 각 플랫폼의 화면 27개·데스크톱 126개 검사, 앱 실행 시작, 두 DMG 마운트, Windows 설치·실행 시작·제거가 통과했다. 일반 CI는 9개 OS·Python 조합에서 646개 통과·3개 건너뜀이며 Qt 포함 로컬 668개와 실행 범위가 다르다.

네 설치 파일을 공개 URL에서 **전체 다운로드**했다. HTTP 200·파일 크기·SHA-256이 `SHA256SUMS.txt`와 GitHub asset digest 모두에 일치했다. [다운로드 검증 원본](../assessment/desktop-release-2026-10-01/release-downloads.json)을 보존했다. README와 설치 안내의 고정 링크는 새 태그로 갱신했다. 기존 1.0.0 미리보기는 유지한다.

게시 후의 별도 Benchmark 실행 `36805454531`은 테스트·평가·아티팩트 생성을 통과했지만 릴리스 첨부에서 `contents: write` 부족으로 403 실패했다. 첨부 권한을 명시하고 데스크톱 미리보기에는 평가 보고서를 추가 첨부하지 않도록 수정했다. 해당 실패 기록은 지우지 않는다. 게시로 시작된 중복 Desktop release `36805454266`은 중단했고, 이후에는 빌드 전 기존 릴리스를 확인한다. 후속 자동화 검증 결과는 [작업 인계](../handoff-2026-10-01.md)에 기록한다.
