# 재추출 시 기존 근거 보존

2026-10-01 · 변경 전 `f0fda3c` · 후속 로컬 소스

과거 결과 문서를 현재 목표로 바꿔 재추출하면 기존 구현 상태와 근거가 초기화되던 문제를 수정했다. 후보 추출은 계속 읽기 전용이며, 화면에서 현재 작업 중인 초안과 항목 ID로 합친 후 사용자가 저장한다. 저장 전 편집도 합치기에 포함한다.

## 적용 규칙

- 기존 항목의 이름·완료 조건·포함 여부·구현 상태·근거·구현 메모·수동 검증 기록·테스트 패턴을 보존한다. 같은 ID의 후보는 문서 출처와 문서의 완료 표시만 갱신한다.
- 직접 추가하거나 재추출에서 찾지 못한 기존 항목도 유지한다. 새 ID의 후보만 뒤에 추가한다.
- 선택 해제한 기존 문서는 참고로 남겨 근거를 지우지 않고 집계에서 제외한다. 합친 결과가 기존 저장 상한인 문서 10개·기능 120개를 넘으면 초안을 대체하지 않는다.
- 문서 해시가 바뀌면 이전 검토 시점의 해시를 보존하고 항목을 재확인 대상으로 처리한다. 재추출을 반복해도 이 상태를 자동 해제하지 않는다. 명시적인 문서 확인으로 새 기준을 적용하고 수동 검증 상태를 미검증으로 바꾼다. 기존 검증 메모는 남긴다.
- 저장된 것과 동일한 코드 근거는 기존 코드 해시와 발췌를 보존한다. 코드가 바뀌거나 없어졌다면 단순 저장으로 유효한 근거로 되돌리지 않는다. 사용자가 근거를 편집했을 때 새 코드 스냅샷을 검증해 저장한다.
- 이전 저장 파일은 계속 읽을 수 있다. 추가 문서 검토 정보가 없는 항목은 기존 출처 해시로 판단한다.

## 범위와 한계

항목 ID는 기존처럼 문서 경로·줄 번호·원래 제목에 기반한다. 줄 이동이나 제목 변경은 새 ID가 될 수 있으므로 이전 항목을 자동으로 삭제하거나 의미가 같은 항목으로 추정해 합치지 않는다. 제거된 출처의 기록은 남고, 이를 새 기준으로 확인하려면 저장 검증을 통과하는 실제 출처가 필요하다. 기록을 더 이상 집계하지 않으려면 해당 항목을 범위에서 제외한다. 기존에 선택했던 문서 파일 자체가 삭제됐을 때의 기준 저장은 기존 유효성 검사에 따라 거부한다.

요약 카드 분리와 테스트 연결 범위 정리 등 평가의 2~5번은 이번 변경에 포함하지 않았다. 커밋·푸시·새 설치 파일 배포는 하지 않았다.
