## 남은 작업과 운영상 한계

1. 새 CI job은 작성 및 로컬 실행 경로 검증까지 완료했다. **이번 수정의 원격 CI와 설치본은 아직 실행하지 않았다.** 이전 `01e28e1`의 설치본 성공을 새 후보의 검증으로 승계하지 않는다.
2. 자체 정책은 경로 기반 문서 갱신 요구다. 문서에 무관한 주석만 추가하는 경우까지 의미상 동기화를 보증하지 않는다. 경로 정책 통과와 지원 계약 내용 검사를 구분한다.
3. `min_change_intensity: impl-only`는 코멘트 전용 변경을 제외하지만 모든 포맷 변경을 정확히 제외하지 못한다. 실제 작업의 불필요한 요구를 관찰해 보수적 초기 정책을 조정해야 한다.
4. CI가 비교할 base SHA를 확보하지 못하면 오류로 종료한다. 새 브랜치 최초 push의 zero SHA도 임의의 HEAD 기준으로 대체하지 않는다. 필요하면 별도 명시 기준을 정하는 운영 절차를 추가해야 한다.
5. 동적 환경 키·별칭·router prefix·chained route·응답 schema 등 경계 사례는 남는다. 다음 개선은 해석 불가 표시와 전후 소스 snapshot 설계부터 시작한다.
6. MCP 도구 전체의 시간 제한/취소, 작업 트리의 원자 snapshot, 전체 ProgressApplicationService 분리는 이번 범위에 포함하지 않았다.

다음 실행 순서는 새 후보의 원격 CI·설치본 확인 → 경계 사례의 지원 범위와 해석 불가 표시 → snapshot 및 조정 계층 정리다. 새 기능 추가보다 현재 검증 계약을 유지하며 작은 단위로 진행한다.
