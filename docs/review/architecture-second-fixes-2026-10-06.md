# 두 번째 아키텍처 리뷰에 따른 운영 코드 수정

2026-10-06, `ver2` 작업 트리. HEAD는 `729a3cde70c3457b633798bb50273d815d4d2c12`이며 이 문서의 변경은 아직 커밋·푸시하지 않았다. 직전 수정과 사용자의 기존 변경을 유지했다. 기존 문서 두 파일의 삭제는 이번 수정에 포함하지 않았다.

기준은 [두 번째 리뷰](architecture-second-audit-2026-10-06.md)와 [목표 설계 v2](../architecture/target-architecture-v2-2026-10-06.md), 그 리뷰의 재현 자료다. 이전 재현 결과는 당시 관찰 기록으로 남기고, 이번 검증은 [별도 자료](../assessment/architecture-second-fixes-2026-10-06/README.md)에 기록했다. 목표 아키텍처 전체를 구현했다는 보고가 아니다.

## 저장과 복구 계약

- 기존 schema 1을 유지한다. `documents`는 출처 해시를 계속 보존하며 `archived_documents`는 명시적으로 연결을 해제한 경로 목록이다. 기존 파일에 이 필드가 없으면 연결 상태를 유지한다. 보관 상태는 기준 식별값에 포함한다.
- 연결 문서 최대 10개, 보관 문서 최대 120개, 확정 기능 최대 120개다. 보관은 파일이나 기능 삭제가 아니다. 문서 보관만으로 기능 상한을 줄이지 않는다.
- 보관할 해시는 이전에 확정된 문서와 같아야 한다. 변경·추출된 새 문서를 임의의 과거 출처로 만드는 우회는 거부한다. 이름 변경을 의미상 같은 목표라고 자동 추정하지 않는다. 새 이름 추출은 새 후보를 추가하고 이전 목표·검토 기록은 보존한다.
- 같은 경로를 다시 선택하고 재추출하면 연결을 복원한다. 변경된 내용은 기존 문서 재확인 규칙을 적용하며 이전 검토를 최신 근거로 자동 갱신하지 않는다.
- 오래된 초안에 식별값이 없더라도 원래 `edit_base`가 있으면 그 식별값으로 비교한다. 둘 다 없고 내용이 바뀌었으면 숫자 버전만 믿지 않고 충돌 처리하여 최신 기준과 명시적으로 합치게 한다.
- 화면에서도 선택 문서 목록·수동 추가·범위 계산·추출 합치기·충돌 합치기에 동일한 연결/보관 구분을 적용한다. 보관 후 요약·검사·이력·테스트·링크 결과는 무효화한다.

## 남은 설계와 한계

- 목표 설계의 generation UUID, 명령 receipt, 영속 command ID, schema 2 이관, 전체 원자 소스 snapshot, 전체 application-service 분리는 이번 구현에 포함하지 않았다. 내용이 완전히 동일한 기준의 재생성까지 다른 세대로 구별하지는 않는다. 내용이 다르면 이번 CAS로 거부한다.
- 이력 anchor는 이 작업 흐름에서 캡처한 실제 목록이다. 영속 sequence/checkout별 partition을 도입한 것은 아니다. 같은 원격의 다른 checkout에서 예전에 기록된 이력의 의미를 완전히 분리하는 기능은 남는다.
- 문서 이름 변경의 명시적 목표별 재연결/매핑 화면은 추가하지 않았다. 기존 목표는 보관하고 새 후보는 별도 검토한다.
- MCP의 각 도구 실행 시간 제한·취소·격리 worker는 남는다. stdio 요청과 출력 크기 제한이 모든 실행 시간 자원 고갈을 해결하지는 않는다.
- 손상 이력은 그대로 보존하고 경고한다. 앱 안에서 파일을 복구하거나 초기화하는 별도 UI는 없다.
- Windows/Linux 새 설치본, 새 패키지의 오프라인 검사, 원격 CI, 공개 릴리스, 판정 정확도 평가는 이번에 실행하지 않았다. 커밋·푸시·릴리스도 하지 않았다.
