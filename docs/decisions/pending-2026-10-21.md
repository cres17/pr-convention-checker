## 1. 커밋 `8a2e77b`, `16f71ef`의 `Claude-Session:` 줄

**무엇을 정하나:** 사용자 규칙(커밋에 AI 작성 표시를 넣지 않음)과 달리 이미 GitHub에 올라간 커밋 2개의 메시지 끝에
`Claude-Session: https://claude.ai/code/session_…` 줄이 있다. 지우려면 git 기록을 다시 써야 한다.

**현재 상태(사실)**
- 두 커밋 모두 해당 줄이 있다(`git log --format='%(trailers:key=Claude-Session)'`로 확인).
- 그 뒤로 커밋 6개가 더 있다. 기록을 다시 쓰면 이 8개 커밋의 해시가 모두 바뀐다.
- 원격 `main`과 `ver2`가 같은 커밋(`be82039`)을 가리킨다. 두 브랜치 모두 force-push가 필요하다.
- 저장소 fork 0개, star 0개(GitHub API). 이 커밋들을 포함하는 태그는 없다.
- 이 대화 밖의 다른 clone(사용자 PC, Codex 작업 공간 등)이 있는지는 확인하지 못했다. 있다면 그쪽은 `git fetch` 후 `git reset --hard origin/main`이 필요하다.

**선택지**
- A. 메시지만 고쳐 다시 쓰고 `main`·`ver2`를 force-push한다. 코드 내용은 바뀌지 않는다.
- B. 그대로 두고 앞으로만 넣지 않는다.

**Opus 선택: A.** 사용자 규칙을 어긴 기록이고, fork·태그가 없어 다시 쓸 때 영향이 이 저장소 안에 한정된다.
단, 다른 곳에 clone이 있으면 먼저 거기서 작업 중인 변경을 push하거나 버린 뒤에 실행해야 한다.
바뀐 해시를 참조하는 문서(예: 계획.md의 커밋 해시)는 새 해시로 고쳐야 한다.

## 2. 주석만 바꾼 변경의 기본 처리 (리뷰 #8)

**무엇을 정하나:** 규칙에 `min_change_intensity`를 적지 않으면 기본값이 `any`라서, 감시 경로의 파일에서
주석 한 줄만 바꿔도 규칙이 발동한다(문서 갱신 요구). 기본값을 `impl-only`(주석만 바뀐 변경은 건너뜀)로 올릴지 정한다.

**현재 상태(사실)**
- 기본값: `drift_gate/core/models/policy.py` `When.min_change_intensity = "any"`.
- `drift-gate init` 프리셋(`adapters/cli/presets.py`)은 이미 규칙마다 `signature-change`, `db-schema-change` 등을 명시한다.
  기본값 변경의 영향을 받는 것은 이 값을 직접 적지 않은 정책뿐이다.
- 2026-10-06 점검(`docs/review/drift-gate-claim-verification-2026-10-06.md` D1)에서 "코드 줄을 주석으로 잘못 판정해 규칙을 건너뛰는" 결함이 실제로 나왔다. 수정된 뒤지만, 주석 판정은 휴리스틱이다.
- 정책 약화 감시(`core/policy/guard.py`)는 두 정책의 값을 비교한다. 기본값 자체가 바뀌면 정책 파일은 그대로라서 약화로 잡히지 않는다.
- 이번 파일럿 정책은 `min_change_intensity`가 아니라 `trigger`를 쓴다. 이 결정은 파일럿 결과에 영향이 없다.

**선택지**
- A. `any` 유지. 문서에 "주석 변경도 발동하므로 필요하면 `impl-only`를 적으라"고 명시한다.
- B. 기본값을 `impl-only`로 바꾼다(기존 정책의 동작이 조용히 바뀜).
- C. 기본값은 두고 `policy validate`가 값이 없는 규칙에 경고를 낸다.

**Opus 선택: A** (C를 더해도 좋다). 기본값 변경은 사용자가 모르는 사이에 기존 정책을 느슨하게 만들고,
약화 감시도 그것을 잡지 못한다. 주석 판정은 한 번 실제로 틀렸던 기능이라 기본으로 켜기에는 근거가 부족하다.
반대 근거도 있다: CLAUDE.md는 "false positive 줄이기가 기능 추가보다 중요"하다고 적고 있고, B가 그 방향이다.

**현재 상태(사실)**

  분석 결과(`semantic_signals`, `documented_env_keys`, `before_routes`/`after_routes`, `env_key_usage` 등)가 한 dataclass에 있다.
- core 밖 8개 파일에서 `ChangedFile(...)`을 직접 만든다(git·github·holdout·snapshot·eval·docs 어댑터 등).
- `from_dict`는 입력 JSON의 `documented_env_keys`, `semantic_signals`도 그대로 받는다. 이것으로 판정을 바꿀 수 있는 입력 경로가 실제로 있는지는 확인하지 않았다.

**선택지**

- B. 파일럿(label → run → score)이 끝난 뒤에 한다. 그 전에는 `from_dict` 입력 경로만 점검한다.
- C. 하지 않는다.

**Opus 선택: B.** 생성 지점이 8곳이라 변경 범위가 크고, 파일럿 직전에 엔진을 크게 바꾸면 고정할 엔진 커밋이 흔들린다.
