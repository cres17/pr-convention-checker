# 삭제된 환경 변수 키 확인

`content: env-keys` 그룹은 새 키가 설정 예제에 있는지 확인하고, 기본으로 삭제된 키가 예제에 남았는지도 확인합니다. 규칙의 `when` 경로에 해당하는 Python과 JavaScript/TypeScript의 정적 환경 변수 접근이 대상입니다. 다른 내용 검사 모드는 영향을 받지 않습니다.

```yaml
rules:
  - id: environment-example
    when:
      any_changed: [src/**]
    require:
      groups:
        - name: 환경 변수 예제
          any_changed: [.env.example]
          content: env-keys
    severity: blocker

# 저장소 밖에서 사용하는 키만 예외로 두기 (권장)
exclude_removed_keys: [LEGACY_TOKEN]
# 삭제 키 검사 전체를 끄려면 다음 줄을 사용합니다.
# check_removed_keys: false
```

두 옵션은 정책 최상위에 둡니다. `check_removed_keys` 기본값은 `true`, `exclude_removed_keys` 기본값은 빈 목록입니다. 키 예외는 와일드카드를 허용하지 않습니다. 예외와 끄기는 삭제 검사에만 적용되므로 새 키의 문서 누락은 계속 검사합니다. `env-keys`를 쓰는 모든 프리셋도 같은 기본값을 따릅니다.

## 판정

코드에서 제거한 키가 지정한 예제 문서에 남았을 때 다음 기준을 적용합니다.

| 저장소에서 확인한 상태 | 판정 |
|---|---|
| 문서를 제외한 검색이 완료됐고 다른 사용·언급이 없음 | 위반. 규칙의 심각도를 적용하며 blocker면 fail |
| Python 또는 JS/TS 코드가 지원하는 정적 형태로 읽음 | 삭제 키 의무는 충족 |
| 설정·배포 파일에 환경 변수 형태로 존재 | advisory → warn |
| 주석·미지원 언어·형태가 다른 언급만 존재 | advisory → warn |
| 전체 검색 또는 전후 소스·문서를 확인하지 못함 | advisory → warn |

문서에서도 키가 제거됐거나 코드가 다른 파일로 이동해 계속 쓰는 경우에는 삭제 키 위반을 만들지 않습니다. 삭제 키 경고만 있으면 `gate.on_unverified: fail`이어도 fail로 올리지 않습니다. 새 키 누락 등 독립적인 위반이나 확인 불가 항목의 기존 판정은 유지합니다.

`advisories`는 규칙의 위반 목록과 분리됩니다. 경고가 있으면 전체 판정의 pass가 warn으로 바뀌며 조직 조치는 `review`입니다. 다른 위반의 fail은 유지합니다. 경고 목록은 사용 여부를 자동으로 확정했다는 뜻이 아닙니다.

## 설정·배포 형태 (Z)

다음 형태는 사용 가능성을 알리는 경고 근거이며, 다른 서비스가 같은 이름을 쓸 수 있어 자동 통과의 근거로 삼지 않습니다.

| 파일 | 인식 형태 |
|---|---|
| `docker-compose*.yml` / `.yaml`, `compose.yml` | `environment:`의 `KEY:` 또는 `- KEY=...`, `${KEY}`, `${KEY:-default}` |
| `Dockerfile*` | `ENV KEY`, `ARG KEY`, `$KEY`, `${KEY}` |
| `.sh`, `.bash`, `.zsh` | `export KEY`, `KEY=...`, `$KEY`, `${KEY}` |
| `.github/workflows/*.yml` / `.yaml` | `${{ secrets.KEY }}`, `${{ env.KEY }}`, `env:`의 `KEY:` |
| Kubernetes / Helm YAML | `env:` 목록의 `name: KEY`, `secretKeyRef:`의 `key: KEY` |

YAML은 제한된 크기·깊이로 읽으며 지원하지 않는 템플릿은 제한적인 들여쓰기 패턴만 확인합니다. 이 패턴 밖의 언급은 이름만 발견한 경고로 남깁니다. 일반 YAML의 `name: KEY`는 환경 변수 사용으로 인정하지 않습니다.

## 검색과 재실행 범위

로컬 CLI·MCP·데스크톱은 Git이 추적하는 현재 파일과 Git에 추가되지 않은 비무시 파일을 검색합니다. 지정한 예제, `docs/`, `doc/`, Markdown·RST 문서는 사용 검색에서 제외합니다. Git이 무시하는 비추적 파일과 저장소 외부의 소비자는 확인하지 않습니다.

불변 커밋 검사는 지정한 head의 Git 트리를 확인합니다. GitHub PR API만 사용하는 경로는 전체 트리 사용 증거를 수집하지 않으므로 삭제 키 후보가 남으면 경고입니다. 변경 전후 소스도 없는 단순 patch 입력은 제거가 확정됐다고 처리하지 않습니다.

추가 검색에는 최대 2,000개 파일·8 MB의 자체 한도가 있습니다. 한도·읽기·문법 분석 제약으로 부재를 확인하지 못하면 경고로 남깁니다. 실행 전체에 지정한 별도 자원 한도는 기존 중단 규칙을 따릅니다. 동적 키·미지원 구문은 정적인 사용을 증명하지 못합니다. 이 기능은 외부 서비스의 실제 사용 여부를 확인하지 않습니다.

검색 결과에는 키 이름·분류·경로만 남깁니다. 관측 결과를 검사 스냅샷에 포함해 재실행 시 검색을 다시 하지 않습니다. 일반 보고서와 실행 이력에는 검색한 소스나 환경 변수 값을 추가하지 않습니다. 사용자가 명시적으로 저장하는 evidence bundle은 기존과 같이 원본 검사 입력을 포함할 수 있습니다.

## CLI·CI·MCP와 데스크톱

CLI·CI·MCP는 실행 중 질문하지 않습니다. 결과 근거와 경고에 키 하나의 예외 및 전체 끄기 방법을 동일하게 표시합니다. JSON에는 `advisories: [{rule_id, key, kind, message, paths}]`가 추가되며 Markdown·HTML·MCP 축약 출력에도 표시합니다. `kind`는 `config`, `mention`, `incomplete`입니다.

데스크톱의 “삭제된 환경 변수 확인”에는 “이 키는 앞으로 탐지하지 않기”와 “삭제 키 검사 끄기” 버튼이 있습니다. 확인창에서 **저장**을 눌렀을 때만 `.drift-gate.yml`에 저장한 뒤 다시 검사합니다. 기본 선택은 취소이고, 취소·Esc·창 닫기는 모두 저장하지 않습니다. 확인창은 모든 OS에서 Qt가 그리는 같은 대화상자를 쓰며, 확인창이 열려 있는 동안 들어온 다른 설정 요청은 거부합니다. 과거 기록에서는 설정 버튼을 제공하지 않습니다. 검사 후 정책이 바뀌었으면 저장을 거부하고 재검사를 안내합니다.

검사를 끄거나 키 예외를 추가하면 `core/policy/guard.py`가 정책 약화로 판정합니다. 별도로 고정한 신뢰 정책을 사용하는 검사에서는 후보 PR의 옵션으로 그 검사를 우회하지 못합니다. 기존 불변 입력 검사는 정책 약화를 입력 오류로 거부하며, 상위 `trusted-check`는 `candidate-policy-weakened` 사유와 함께 `review`를 반환하며 병합 근거를 `none`으로 둡니다. 일반 로컬 검사는 현재 정책을 사용하므로 예외 저장 후에는 해당 삭제 키가 탐지되지 않습니다.
